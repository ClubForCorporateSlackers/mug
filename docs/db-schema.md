# DBスキーマ（案）蚊に刺された場所を共有するアプリ

作成：小松（バックエンド担当）／ 作成日：2026-11-16 ／ 状態：**案**

APIは [api-spec.md](./api-spec.md) を参照。

---

## 1. 方針

- DB：**DynamoDB**（プロビジョンドモード、東京リージョン）
- テーブルは5つ。**全テーブルの合計で、読み書き各25ユニット以内**に収める（無料枠）
- Auto Scaling、PITR、バックアップ、Streamsは使わない
- **元の座標は保存しない**。保存するのは100mずらした後の位置だけ
- ピンには投稿者の `userId` を保存する（ランキングで数えるため）。ただし**APIでは返さない**

---

## 2. テーブル一覧

| テーブル | 保存するもの | パーティションキー | ソートキー | 書き | 読み |
|---|---|---|---|---|---|
| Users | プロフィール | `userId` | なし | 2 | 3 |
| Pins | ピン | `cell` | `sk` | 3 | 10 |
| Comments | コメント | `pinId` | `sk` | 2 | 3 |
| Reactions | スタンプ | `pinId` | `sk` | 2 | 3 |
| Rankings | ランキング用の件数 | `pk` | `key` | 5 | 4 |
| **合計** | | | | **14** | **23** |

GSIは使わない（ユニットを節約するため、ランキングは件数のテーブルで持つ）。

---

## 3. 各テーブルの中身

### Users

```json
{
  "userId": "a1b2c3…",          // CognitoのID（sub）
  "nickname": "こまつ",
  "bloodType": "A",              // A / B / O / AB / UNKNOWN
  "pinCount": 3,                 // 立てたピンの数（GET /api/me で返す）
  "createdAt": "2026-11-16T10:00:00+09:00",
  "updatedAt": "2026-11-16T10:00:00+09:00"
}
```

- `pinCount`：プロフィール登録（PUT /api/me）のときに `0` を入れる。変更のときは 0 に戻さない（`if_not_exists`）。ピンを立てるたびに `ADD pinCount 1` で増やす
- `pinCount` ができる前に登録した人には、この項目がない。その場合 API は `0` として返し、次にピンを立てたとき（`ADD` はない項目にも使える）か、プロフィールを変更したときに入る

### Pins

```json
{
  "cell": "xn76",                // ずらした位置のgeohash（4文字＝経度0.35度×緯度0.18度、日本付近で約32km×20km。decisions.md #25）
  "sk": "2026-11-16T10:30:00+09:00#01JD…",   // 日時#pinId（新しい順に並べるため）
  "pinId": "01JD…",               // ULID。APIでは cell を付けた「xn76-01JD…」の形で見せる（api-spec.md）
  "lat": 35.6815,                // ずらした後の緯度
  "lng": 139.7668,               // ずらした後の経度
  "city": "東京都千代田区",
  "cityCode": "13101",           // 国土地理院APIのmuniCd（5桁にそろえる。不明なら null）
  "stamp": "kayui",              // なしなら null
  "memo": "公園のベンチ",         // なしなら ""
  "userId": "a1b2c3…",           // 返さない
  "bloodType": "A",              // 立てたときの血液型。返さない（2026-11-19 より前のピンにはない）
  "commentCount": 2,
  "reactions": { "odaiji": 3, "kaite": 1 },
  "createdAt": "2026-11-16T10:30:00+09:00"
}
```

- `bloodType`：ピンを消したときに、立てたときの血液型の件数を減らすために保存する（あとでプロフィールの血液型を変えても、ずれないように）。この項目がない古いピンは、消すときに今のプロフィールの値を使う（decisions.md #34）
- 位置を直す（PATCH）と `lat`・`lng`・`city`・`cityCode` が変わる。`cell`・`sk` は変わらない（同じ `cell` の中でしか動かせない。decisions.md #32）

**地図の範囲で取るとき**：表示範囲にかかる `cell` を計算し、それぞれを `Query`（新しい順、`Limit` 200）。結果を範囲で絞り込み、合計200件まで返す。0.5度四方の範囲でも `cell` は最大12個（5文字だと最大169個になり、読み込みユニットが足りないため4文字にした）

### Comments

```json
{
  "pinId": "01JD…",              // ピンの ULID（APIの pinId から「cell-」を除いたもの）
  "sk": "2026-11-16T11:00:00+09:00#01JE…",   // 日時#commentId（古い順に並べるため）
  "commentId": "01JE…",
  "userId": "d4e5f6…",
  "nickname": "しばた",          // 投稿時点のニックネームをコピーして保存
  "text": "お大事に！",
  "createdAt": "2026-11-16T11:00:00+09:00"
}
```

### Reactions

```json
{
  "pinId": "01JD…",
  "sk": "odaiji#d4e5f6…",        // 種類#userId（1人1種類1回にするため）
  "type": "odaiji",
  "userId": "d4e5f6…",
  "nickname": "しばた",
  "createdAt": "2026-11-16T11:05:00+09:00"
}
```

押した・取り消したときは、Pinsの `reactions` の件数も合わせて増減する（地図表示で毎回数えなくて済むように）。Reactions と Pins はトランザクションでまとめて書く（二重に押しても件数がずれないように。docs/adr/feature-api-social.md）。取り消して0件になった種類は `0` のまま残る（APIでは返さない）。

### Rankings

```json
{ "pk": "2026-11#user",  "key": "a1b2c3…",  "label": "こまつ",         "count": 12 }
{ "pk": "2026-11#city",  "key": "13101",    "label": "東京都千代田区", "count": 30 }
{ "pk": "2026-11#blood", "key": "A",        "label": "A型",            "count": 25 }
```

- 血液型の `label` は `A型`／`B型`／`O型`／`AB型`、`UNKNOWN` は `不明`
- 市町村が「不明」のピンは、市町村の件数を増やさない

- ピンを立てるたびに、その月の3つの件数を `ADD count 1` で増やす
- ランキングを見るときは `pk`（例：`2026-11#user`）で `Query`（`Limit` 1000）して、Lambdaの中で件数の多い順に並べる。血液型の `UNKNOWN` は返さない

## 4. 操作ごとの読み書き

| 操作 | 書き込み | 読み込み |
|---|---|---|
| プロフィール登録 | Users 1件 | なし |
| ピンを立てる | Pins 1件＋Rankings 3件＋Users 1件（`pinCount` を1増やす） | Users 1件（ニックネーム・血液型を確認） |
| 地図を開く | なし | Pins（範囲内のcell数ぶんQuery） |
| コメントする | Pins 1件（件数。ピンがなければ404）→ Comments 1件 | Users 1件 |
| コメント一覧 | なし | Pins 1件（あるかの確認）＋Comments 1回Query（最大100件） |
| スタンプを押す・取り消す | Reactions 1件＋Pins 1件（件数）を**トランザクション**で（各2ユニット） | Users 1件＋Pins 1件（強い整合性）＋Reactions 2件（自分が押したか） |
| ランキングを見る | なし | Rankings 1回Query |
| 自分のピンを直す（スタンプ・メモ） | Pins 1件（条件付き。前の値を受け取る） | なし |
| 自分のピンを直す（位置。市町村が変わったとき） | Pins 1件＋Rankings 2件 | なし |

ピンを立てる操作は**書き込み5件**（Pins 1・Rankings 3・Users 1）。Pins（3）・Rankings（5）・Users（2）のユニットで、平常時でも1秒に1件程度は問題なく処理できる。
