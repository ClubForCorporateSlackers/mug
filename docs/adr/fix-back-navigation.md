## 判断：たどってきた画面の履歴を App に持ち、「戻る」はそれを1つ戻る

- 状態：提案（人の確認待ち）

### 状況（何に迷ったか）

田中の指摘（11/19）：プロフィールの編集をマイページから開いて「戻る」を押すと、マイページではなくマップに戻る。調べると、「戻る」の行き先を画面ごとに決め打ちにしていたため、ほかにも同じことが起きていた。

| 画面 | 来る道 | 前の「戻る」 |
|---|---|---|
| プロフィール | マイページ | いつもマップ |
| アカウント作成 | はじめの画面（「はじめる」） | いつもログイン |
| 確認コード | ログイン（メールの確認がまだのとき） | いつもアカウント作成 |
| ログイン | ピンの詳細・マイページ・ほか | 決め打ちの行き先か、はじめの画面 |

### 決めたこと

- `App.tsx` に、たどってきた画面の一覧（`history`）を持つ。次の画面へ進むときは今の画面を積み（`push`）、「戻る」は1つ前に戻る（`back`）。履歴がないときだけ、前の決め打ちの行き先に戻る
- 次のときは履歴を空にする：下のタブを切り替えたとき、ログイン・登録が終わったとき、ログアウトしたとき（終わったあとに「戻る」でログインの画面へ戻らない、タブをまたいで戻らないため）
- パスワードの再設定が終わったら、再設定の2つの画面は飛ばして、もとのログインの画面に戻る
- プロフィールを保存したら、マイページから来たときはマイページへ戻る。初めての登録のときは、今まで通り次の画面（マップなど）へ進む

### 理由

画面が増えても、それぞれに行き先を書かなくて済む。利用者が期待する「1つ前に戻る」と同じ動きになる。

### ほかの案

- 画面ごとに行き先を直す：来る道が増えるたびに直す必要があり、また同じことが起きるのでやめた
- ブラウザの「戻る」（スワイプで戻る）とつなぐ（History API）：今回は画面の中の「戻る」ボタンだけにした。ブラウザの「戻る」は今もアプリの外（前のサイト）に出る

### 影響・あとで見直すこと

- iPhone のスワイプやブラウザの「戻る」でも1つ前の画面に戻るようにするかは、別に決める
