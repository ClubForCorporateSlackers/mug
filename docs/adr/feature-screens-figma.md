## 判断：ピンは「完了」を押したときに1回で投稿する（Figma は「押した瞬間に投稿」）

- 状態：提案（人の確認待ち）

### 状況（何に迷ったか）

Figma（B4・Button / Sasareta の説明）は「ワンタップで投稿し、スタンプ・コメントは投稿後に任意で追加」。今の API には、投稿後にスタンプ・メモ・位置を変える API（PATCH）も、取り消す API（DELETE）もない。

### 決めたこと

見た目は Figma の B4〜B6 のまま、「ここで刺された！」でシートを開き、「完了」で `POST /api/pins` を1回だけ呼ぶ。B5 の位置の調整も、B6 の取り消しも、投稿の前に行う。シートの見出しは「ピンを立てました！」ではなく「ここにピンを立てます」にした。

### 理由

今の API だけで、スタンプ・メモ・位置の調整・取り消しがすべて本当に動く。押した瞬間に投稿すると、あとから付けたスタンプやメモを保存できない。

### ほかの案

- Figma どおり即投稿し、スタンプ・メモ・取り消しは「準備中」にする：デモで一番使う機能が動かなくなるのでやめた

### 影響・あとで見直すこと

PATCH・DELETE が追加されたら、Figma どおりの「即投稿」に戻せる（`MapPage.tsx` の `startPost` と `submitPost`）。

## 判断：スタンプ・リアクション・ランキングの種類は、Figma ではなく決定済みの仕様に合わせた

- 状態：提案（人の確認待ち）

### 状況（何に迷ったか）

Figma と仕様が食い違っていた。

| 項目 | Figma | 仕様（決定済み） |
|---|---|---|
| ピンのスタンプ | かゆい・お大事に・ここ多い・じわじわ | かゆい・いたい（api-spec 5、app-spec F-07 ✅） |
| リアクション | 8種類 | お大事に・掻いてあげる・わかる（API が受け付けるのはこの3つ） |
| ランキングの種類 | 刺された回数・血液型別の2つ | 人・市町村・血液型の3つ（decisions #10） |
| 血液型の5つ目 | 不明 | 答えない（app-spec F-02 ✅） |
| アプリ名 | 刺されMAP | mug（decisions #17） |

### 決めたこと

すべて右の「仕様」に合わせた。見た目（丸いアイコン、赤い枠の選択など）は Figma のまま。血液型のグラフは、API が返す件数をそのまま出す（Figma の「1人あたりの平均」は API がないので出さない）。

### 理由

チームの決定を優先する指示のため。API が受け付けない値を画面に出すと、押してもエラーになる。

### ほかの案

なし。

### 影響・あとで見直すこと

Figma 側も仕様に合わせて直すと、見比べるときに迷わない。

## 判断：API がない機能は、画面とボタンだけ作り「準備中です（APIの追加待ち）」と出す

- 状態：提案（人の確認待ち）

### 状況（何に迷ったか）

田中の指示：「今の API で作れない機能も一旦画面に描画し、PR で Manato さんに追加実装を頼む」。

### 決めたこと

- ボタンを押すと「準備中です（APIの追加待ち）」と出す（B9 通報・非表示、B10 自分のピンの調整・編集・削除、D6 アカウント削除）
- 数字は「—」にする。本物に見えるダミーの数字は出さない（地図の危険度、D1 の今月の回数・もらったお大事に）
- 文章で「準備中です」と書く（C1 のいまいる市町村の順位、C2 の自分の今月の回数、D2 の自分のピン一覧）
- コードには `// TODO(API): …` を付けた。`grep -rn "TODO(API)" frontend/src` で一覧が出る
- 地図の上のカードは、エリア名の API がないので「表示中のエリア」とし、件数は読み込んだピンのうち今月のものを数える
- B10（自分のピンのメニュー）は、この画面を開いている間に自分で立てたピンだけで出す（ピンの API は userId を返さないため）

### 理由

デモで「本物のデータ」と誤解されないようにするため。

### ほかの案

- ダミーの数字を出す：本物と区別がつかないのでやめた
- 画面ごと作らない：指示と違うのでやめた

### 影響・あとで見直すこと

API ができたら TODO(API) の所を差し替える。

### ほかの案

なし。

## 判断：パスワードの説明は Cognito の条件に合わせ、「利用規約に同意」の文は出さない

- 状態：提案（人の確認待ち）

### 状況（何に迷ったか）

Figma の A2 は「英字と数字を両方ふくめてください」「続けると、利用規約とプライバシーポリシーに同意したことになります」。実際の Cognito は大文字・小文字・数字・記号がすべて必要。利用規約とプライバシーポリシーはまだない。

### 決めたこと

説明は「8文字以上で、大文字・小文字・数字・記号をふくめてください」にした。同意の文は出さない。D1 の「利用規約」「プライバシーポリシー」は「準備中です」と出す。

### 理由

条件が違うと、登録で必ず失敗する。ない規約に同意させる文は出せない。

### ほかの案

なし。

### 影響・あとで見直すこと

パスワードの条件をゆるめる（app-spec F-01 🟡）なら説明も直す。規約ができたら同意の文を戻す。

## 判断：shadcn/ui の部品を4つ追加し、古いページと部品を消した

- 状態：提案（人の確認待ち）

### 状況（何に迷ったか）

Figma の画面に合わせると、前の画面の作りの多くが使えなくなった。

### 決めたこと

- shadcn/ui の `input`・`sheet`・`alert-dialog`・`input-otp` を追加した（`input-otp` は新しい依存）。`button.tsx` は上書きしていない
- 消したもの：`SplashPage`・`ComposePage`・`PinPage`・`ProfilePage`（A1・B4・B7・A4/D4 に置き換え）、`BottomNav`（→ `TabBar`）、`ScreenHeader`（→ `NavBar`）、`MugMemo`（→ `PostPanel` の中の入力欄）
- `cn` の読み込み元を、frontend/AGENTS.md のとおり `@/lib/utils` にそろえた（自分で書いたファイルだけ。`ui/` は shadcn のまま）

### 理由

frontend/AGENTS.md の「shadcn にある部品を一から書かない」を守るため。使わないファイルを残すと迷うため。

### ほかの案

なし。

### 影響・あとで見直すこと

`HomePage`・`ApiCheckCard`（最初の土台）はどこからも使われていないが、この作業の外なので残した。

## 判断：地図の出典表示は、ボタンより上に出す（MapLibre の CSS を1か所だけ ! で上書き）

- 状態：提案（人の確認待ち）

### 状況（何に迷ったか）

出典表示（消してはいけない。AGENTS.md）が「ここで刺された！」ボタンに重なって読めなかった。MapLibre の CSS は Tailwind の層の外で読み込まれているので、ふつうのクラスでは位置を変えられない。

### 決めたこと

`MapSurface` で、出典表示の位置を `[&_.maplibregl-ctrl-bottom-left]:bottom-[…]!` で上書きした。

### 理由

`style` も新しい CSS ファイルも使わずに直せる、いちばん小さい変更のため。

### ほかの案

- `index.css` で MapLibre の CSS を層に入れる：地図のほかの見た目まで変わるおそれがあるのでやめた

### 影響・あとで見直すこと

なし。

## 判断：A1 の黄色い地に赤い文字（コントラスト不足）は Figma のままにした

- 状態：提案（人の確認待ち）

### 状況（何に迷ったか）

Lighthouse で「ログイン」ボタン（赤 #d62f33 ／黄 #ffe08a）のコントラストが 3.77（基準 4.5）と出た。アクセシビリティの点数は 93 で、CI の基準（90）は満たしている。

### 決めたこと

Figma の色のままにした。

### 理由

まずは Figma に合わせる指示のため。

### ほかの案

- 文字を濃い色にする：Figma と変わるので、デザインの担当と相談してから

### 影響・あとで見直すこと

デザインの担当と相談して、色を変えるか決める。
