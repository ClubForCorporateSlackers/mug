## 判断：ピンは「完了」を押したときに1回で投稿する（Figma は「押した瞬間に投稿」）

- 状態：却下（田中、11/18。「ボタンを押したらすぐ刺せる」ようにする。下の「押した瞬間に立てる」に置き換え）

### 状況（何に迷ったか）

Figma（B4・Button / Sasareta の説明）は「ワンタップで投稿し、スタンプ・コメントは投稿後に任意で追加」。今の API には、投稿後にスタンプ・メモ・位置を変える API（PATCH）も、取り消す API（DELETE）もない。

### 決めたこと

見た目は Figma の B4〜B6 のまま、「ここで刺された！」でシートを開き、「完了」で `POST /api/pins` を1回だけ呼ぶ。B5 の位置の調整も、B6 の取り消しも、投稿の前に行う。シートの見出しは「ピンを立てました！」ではなく「ここにピンを立てます」にした。

### 理由

今の API だけで、スタンプ・メモ・位置の調整・取り消しがすべて本当に動く。押した瞬間に投稿すると、あとから付けたスタンプやメモを保存できない。

### ほかの案

- Figma どおり即投稿し、スタンプ・メモ・取り消しは「準備中」にする：デモで一番使う機能が動かなくなるのでやめた

### 影響・あとで見直すこと

PATCH・DELETE が追加されたら、Figma どおりの「即投稿」に戻せる（`MapPage.tsx` の `startPost` と `submitPost`）。

### 状況（何に迷ったか）

### ほかの案

なし。

### ほかの案

なし。

### 影響・あとで見直すこと

## 判断：デモ用アカウントで本当にログインする「デモ用アカウントで入る」を足した

- 状態：提案（人の確認待ち）

### 状況（何に迷ったか）

田中の指示（11/18）：「デモで入ったら、ログインしたことにしてほしい。本物の API は使う」。本物の API は Cognito の IDトークンがないと書き込みを受け付けない（AGENTS.md：userId はトークンの `sub` から取る）。

### 決めたこと

- A1「ようこそ」に「デモ用アカウントで入る」を足した。押すと、デモ用アカウントで Cognito に本当にログインする。そのあとは通常のログインと同じで、投稿・コメント・リアクション・マイページが本物の API で使える
- アカウントのメールアドレスとパスワードは `frontend/.env` の `VITE_DEMO_EMAIL`・`VITE_DEMO_PASSWORD` にだけ書く（`.env.example` は空のまま）。どちらかが空ならボタンを出さない
- デモ用アカウントは、画面の「はじめる（新規登録）」から人が作る（AI は作らない）

### 理由

Lambda の JWT の検証を変えずに、本物の API をそのまま使えるため。パスワードをコードやリポジトリに書かないため。

### ほかの案

- ログインなしで書き込める入口を API に作る：JWT の検証の約束（AGENTS.md）に反し、だれでも書き込めてしまうのでやめた
- 画面の中だけの見せかけ（モック）にする：本物の API を使いたいという指示と違うのでやめた
- 「ログインせずに見る」（見るだけ）：書き込みのたびにログインを求められるので、指示と違った（取り消し済み）

### 影響・あとで見直すこと

- **`VITE_` で始まる値はビルドで画面の JavaScript に埋め込まれる。デモ用アカウントのパスワードは、画面を開いた人なら取り出せる**（手元のビルドで確認済み）。そのため：
  - デモ用アカウントは、デモ専用の新しいアカウントにする（本人のアカウントやほかで使うパスワードを使わない）
  - 取り出した人が、デモ用アカウントでピンやコメントを書いたり、ニックネームを変えたり、Cognito の機能でパスワードの変更やアカウントの削除をしたりできる。困るのはデモ用アカウントだけで、ほかの人のデータには触れない
  - 本番（Workers Builds）に設定するのはデモの間だけにし、終わったら値を消してパスワードを変える
- 本番のプレビューで使うには、Workers Builds のビルド変数に2つを設定する必要がある（小松の作業）

## 判断：「ここで刺された！」を押した瞬間にピンを立て、スタンプとひとことはあとから任意で付ける。出典表示は地図の一番下にする

- 状態：提案（人の確認待ち）

### 状況（何に迷ったか）

田中の指示（11/18）：「ピンはボタンを押したらすぐ刺せるようにし、そのあとコメントやスタンプを残せるシートに移る。それは任意」「OpenFreeMap の出典は地図の一番下、その上に『ここで刺された！』」。前は「完了」を押すまで投稿しなかった（上の却下した判断）。

### 決めたこと

- 押すと、画面の中央の位置で `POST /api/pins`（スタンプなし・ひとことなし）をすぐ呼ぶ。立てたピンを大きく出し、合わせた場所の半径100mの円を出して、B4 のシート「ピンを立てました！」を開く
- シートの「完了」：スタンプもひとこともなければ閉じるだけ。どちらかあれば `PATCH /api/pins/{pinId}`（`{ stamp, memo }`）を呼ぶ
- シートの「取り消す」：確認のあと `DELETE /api/pins/{pinId}` を呼ぶ
- `PATCH`・`DELETE` は**まだ API がない**。404・405 が返ったら「準備中です（APIの追加待ち）」と出す。ピンは立ったまま残る。API ができればそのまま動く（形は PR で Jiji824 さんにお願いした案）
- × は閉じるだけ（ピンはそのまま）
- `api()` で `PATCH` を使えるようにし、本文の SHA-256（約束3）も付ける。Worker はどのメソッドも中継する
- 出典表示は地図の一番下（下のタブのすぐ上）に置き、「ここで刺された！」と現在地のボタンはその上に置く

### 理由

指示のとおり。アプリの目的（刺されたらすぐ記録する）にも合う。

### ほかの案

- スタンプ・ひとことを、自分のピンへのコメントとして送る：コメントはニックネーム付きになり、「メモは匿名」の約束（decisions #8）に反するのでやめた

### 影響・あとで見直すこと

- **`PATCH /api/pins/{pinId}` ができるまで、スタンプとひとことは保存されない**（今立てたピンは、スタンプなし・ひとことなしになる）。API の優先度は一番高い
- `DELETE` ができるまで、立てたピンを取り消せない

## 判断：追加予定の API の形を docs/api-spec.md に書き、画面はその形で呼ぶ（「準備中」の表示はやめる）

- 状態：提案（人の確認待ち。API の形は Jiji824 さんの確認待ち）

### 状況（何に迷ったか）

田中の指示（11/18）：「想定の動きで実装し、Jiji824 さんが API を実装したら動くようにしてほしい」。API の形がバラバラに想像されると、画面とバックエンドが噛み合わない。

### 決めたこと

- docs/api-spec.md に「8. 追加予定のAPI（案）」を足し、#10〜#17 と、今ある API に足す項目の形を書いた
- 画面はその形で呼ぶ。API がないあいだは、返ってきたエラーの `message` をそのまま出す（「準備中」とは出さない）

| 画面 | 呼ぶ API |
|---|---|
| B4 立てた直後のスタンプ・ひとこと、B10 コメントを編集・位置の調整 | `PATCH /api/pins/{pinId}` |
| B6 取り消す、B10 削除 | `DELETE /api/pins/{pinId}` |
| 自分のピンの見分け（B10 のメニュー）、D1・D2 | `GET /api/me/pins` |
| B7 を開いたときの、自分が押したリアクション | `GET /api/pins/{pinId}/reactions` |
| 地図の上のカード（市町村・今月の件数・危険度）、C1 のいまいる市町村の順位、C4 の現在地 | `GET /api/area` |
| 地図の危険エリアの円 | `GET /api/risk-areas` |
| B9 通報 | `POST /api/pins/{pinId}/report` |
| D6 アカウント削除 | `DELETE /api/me` |
| D1 の今月の回数・もらったお大事に、C2 の「あなたは今月○回」 | `GET /api/me` の `monthCount`・`odaijiReceived` |
| C4 都道府県で絞る、C2 の1人あたりの平均 | `GET /api/rankings` の `prefecture`・`average` |

- 読むだけの API（エリア・危険エリア・自分のピン・リアクション）は、失敗したら静かに今までの表示に戻す（例：カードは「表示中のエリア」と、読み込んだピンから数えた件数）。書き込み（PATCH・DELETE・通報）は、失敗したらエラーを出す
- B9「非表示にする」は API を使わず、その端末の localStorage に覚える
- マイページ・自分のピン一覧からピンを押すと、地図でそのピンを開く

### 理由

API の形を1か所に決めておけば、バックエンドはそれに合わせるだけで画面が動く。形を変えたいときも、仕様書を見れば画面のどこに影響するか分かる。

### ほかの案

- 「準備中」と出す：指示と違うので取りやめた（上の却下した判断）

### 影響・あとで見直すこと

- 仕様書の #10〜#17 の形が変わったら、画面も直す（`MapPage`・`MePage`・`MyPinsPage`・`RankingPage`）
- 利用規約・プライバシーポリシーは API ではなくページの中身がないので、まだ「準備中です」と出る
