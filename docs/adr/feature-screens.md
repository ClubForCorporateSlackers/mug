# feature/screens

## 判断：画面は Figma の流れで、地図は OpenFreeMap

状態：提案（人の確認待ち）

Figma（mug）の画面を、認証・地図・投稿・ピン詳細・ランキング・蚊のいいところ・自分、に分けて実装した。地図の見た目は Figma では黄色い紙面に蚊のピンが並んでいるが、仕様（decisions.md #21）に合わせて OpenFreeMap の Positron を使い、ピンだけ蚊のマークにした。Vite では地図の裏側処理の場所がずれるため、配布ファイルを直接指定する。

## 判断：ログインは amazon-cognito-identity-js

状態：提案（人の確認待ち）

メールとパスワード、確認コードは Cognito をブラウザから直接呼ぶ。IDトークンは `X-Id-Token` で既存の `api()` に渡す。プールIDとクライアントIDは README の公開値を、環境変数が空のときの初期値にした。ライブラリが Node の `global` と `Buffer` を参照するため、起動時にブラウザへ足す。

## 判断：入力欄は shadcn の Input を足さず、基本コンポーネントで包んだ

状態：提案（人の確認待ち）

`MugField` と `MugMemo` は、ボタンと同じくトークン色の角丸にした。shadcn の input コマンドは、この環境では後から足せる。

## 判断：手元の /api 転送は証明書の検証を外す

状態：提案（人の確認待ち）

プロキシ環境では証明書のエラーが出ることがあるため、`vite.config.ts` の開発用の転送に `secure: false` を付けた。本番の Worker には影響しない。

## 判断：都道府県の絞り込みは、返ってきた上位20件に対して行う

状態：提案（人の確認待ち）

`GET /api/rankings` に都道府県のパラメータはない。Figma の「都道府県」は、返ってきた市町村名の先頭が一致するものだけを表示する。

## 判断：Figma の更新分は、画面だけで済むものを実装した

状態：提案（人の確認待ち）

API や仕様の変更が要るものは、今回入れていない。「すぐ投稿して、あとで取り消す」（B4・B6）、ほかの人のピンの通報・非表示（B9）、自分のピンの位置・コメント編集と削除（B10）、自分のピン一覧（D2・D3）、アカウント削除（D6）、Google Maps への切り替え（decisions.md #21 と食い違う）。どれも人の確認を待つ。

## 判断：投稿は今まで通り「投稿する」を押したときに送る

状態：提案（人の確認待ち）

Figma は先に立ててからスタンプとメモを足すが、ピンを変更・削除する API がない。そこで同じ見た目の下書きの画面にし、「投稿する」を押した時点で `POST /api/pins` を送る。下書き中にやめると「投稿をやめますか？」を出す。位置の調整（B5）は、中央のピンに合わせて地図を動かす。

## 判断：ランキングは「刺された回数」と「血液型別」の2つ

状態：提案（人の確認待ち）

Figma の切り替えに合わせ、人のランキングの画面はなくした（API はそのまま）。月の絞り込みは直近5か月。

## 判断：リアクションは API の3種類だけ

状態：提案（人の確認待ち）

Figma は8種類並んでいるが、API で使える「お大事に」「掻いてあげる」「わかる」の3つだけにした。ほかを足すには API の変更が要る。

## 判断：マイページの数字は「これまでに立てたピン」だけ

状態：提案（人の確認待ち）

Figma には別の数字もあるが、`GET /api/me` が返すのはピンの件数だけなので、それだけを出す。マイページへは、マップ右上のボタンから入る（下のタブは Figma どおり3つ）。

## 判断：位置情報の案内（A8）は最初の1回だけ出す

状態：提案（人の確認待ち）

ブラウザがまだ許可を聞いていないときだけ出す。「あとで」を選んだことは localStorage の `mug.locationAsked` に残す（位置そのものは保存しない）。オフのときは地図に帯を出し、「ここで刺された！」を押せなくする。

## 判断：色とはばを Figma に寄せた

状態：提案（人の確認待ち）

`--secondary` を黄色にし、ランキングの2位・3位に `--chart-1`（オレンジ）と `--chart-4`（黄色）を使う。PC では Figma の E1 に合わせ、画面のはばを 430px にして中央に置く。

## 判断：パスワードの再設定は Cognito を直接呼ぶ

状態：提案（人の確認待ち）

A6・A7 の画面は、Cognito の `forgotPassword` と `confirmPassword` を使う。Lambda と API は変えていない。
## 判断：蚊のアイコンを、もらった画像の形に描き直した

状態：提案（人の確認待ち）

`MugMark` を画像と同じ形（触角・白目と黒目・ほお・ピンの形の口）にし、地図のピン・現在地・投稿中の場所・favicon も同じ絵にした。画像の色に合わせて、`--mug-body`（頭）・`--mug-pupil`（黒目）・`--mug-cheek`（ほお）の3つの色を `index.css` に足した。favicon はただの画像ファイルなので、色の値を直接書いている。口の先が地点を指すので、地図には下の端を合わせて置く。

## 判断：地図では、断られていなければ毎回現在地を取りに行く

状態：提案（人の確認待ち）

iPhone の Safari は、許可したあとでも「まだ聞いていない」と返すことがあり、前は東京駅のままになっていた。今はブラウザに断られたとき以外は毎回現在地を取りに行き、取れるまでは「現在地を確認しています」を出す。A8 の案内は今まで通り最初の1回だけ。GPS で時間切れになったら、精度を下げてもう一度取る。現在地には大きい蚊のピンを置く（サーバーには送らない）。

## 判断：地図を動かしたときの読み込みは、止まってから0.4秒後に1回だけ

状態：提案（人の確認待ち）

動かすたびに `GET /api/pins` を送っていて、応答が重なるとピンが二重に増えていた。止まってから0.4秒待って1回だけ読み、古い応答は捨て、同じピンは作り直さない。DynamoDB の読み込みの上限にも当たりにくくなる。

## 判断：下のタブは画面の下にくっつける

状態：提案（人の確認待ち）

ランキングなど長い画面で、タブがいっしょに流れていたので、`BottomNav` を画面の下に固定（sticky）した。
## 判断：現在地は Google マップと同じ青い点にし、歩くとついてくる

状態：提案（人の確認待ち）

地図の現在地は、蚊ではなく青い点（白いふち・うすい輪）にした（`HereDot`）。投稿の画面のピンは蚊のままで、口の先に青い点を付けて刺した場所をはっきり見せる（`PostPin`）。青い点の色として `--here` を `index.css` に足した。位置情報がオンの間は `watchPosition` で現在地を追いかける（位置は画面の中だけで使い、サーバーには送らない）。

## 判断：地図の縮小は制限せず、ピンの読み込みだけを0.5度までにする

状態：提案（人の確認待ち）

`GET /api/pins` は縦横0.5度より広い範囲を受け付けない（docs/api-spec.md）。一度、地図の縮小の限界（minZoom）を付けたが、人の指示で外した。地図はどこまでも縮小でき、表示範囲が縦か横で0.5度を超えたときだけ、ピンを読み込まずに「範囲が広すぎます。拡大してください」と出す。

## 判断：地図のピンは30秒ごとに読み直す

状態：提案（人の確認待ち）

地図を開いたままだと、ほかの人が立てたピンが出なかった。見ている間（タブが表に出ている間）は30秒ごとに読み直し、タブに戻ったときにも読み直す。また、地図を動かしたあとに読み込まれないことがあった（`map.loaded()` はタイルの読み込み中に false になるため）ので、最初の読み込みが済んだかを自分で持つようにした。
## 判断：現在地は、蚊のピンの先に青い点を付けた形にする

状態：提案（人の確認待ち）

前の「青い点だけ」から、人の指示で、蚊のピンの口の先に Google マップと同じ青い点（うすい輪つき）を付けた形（`HerePin`）に変えた。青い点の中心が現在地。

## 判断：危険度は、画面の上で近いピンの数で決める

状態：提案（人の確認待ち）

画面の上で64px以内にあるピンを1つのかたまりにし、1個は「小」、2個は「中」、3個以上は「大」とした。かたまりごとに色の違う円を描き、地図の真ん中（＋のしるし）が入っている円の危険度を、上のカードに「危険度 大」のように出す。どの円にも入っていなければ出さない。ズームすると画面の上の距離が変わるので、ズームのたびに数え直す。円の色は MapLibre の描画に直接渡すため、トークンではなく色の値で書いた（`src/lib/danger.ts`）。サーバーの集計は使っていないので、表示中のピン（最大200件）だけで決まる。

## 判断：はじめの画面は Figma（写真1）に合わせ、「はじめる」は新規登録へ

状態：提案（人の確認待ち）

タイトルを「刺されMAP」にし、できること3つを並べた。「はじめる（新規登録）」は新規登録の画面へ、「ログイン」はログインの画面へ進む。前にあった「近くの地図を見る」（ログインせずに見る入口）はなくなった。

## 判断：マイページの位置情報をスイッチにした

状態：提案（人の確認待ち）

shadcn/ui の `switch` を追加し、`SwitchRow` で包んだ。ブラウザの許可そのものはアプリから取り消せないので、オフにするとアプリが位置情報を使わなくなる（現在地の点を消し、ピンを立てられなくする）。オフにしたことは localStorage の `mug.locationOff` に残す（位置そのものは保存しない）。地図の「許可する」かスイッチでオンに戻る。

## 判断：自分のピンの編集・削除、自分のピン一覧、今月の回数・もらったお大事に、は今回入れない

状態：提案（人の確認待ち）

どれも API とDBの変更が要る（ピンの API は匿名で、自分のピンかどうかがわからない。ピンを変更・削除する API がない。ユーザーごとにピンを引く仕組みがDBにない。`GET /api/me` は合計の件数だけ）。人と相談して、今回は画面だけで済むものを先に入れ、API はJiji824さんと相談してから作ることにした。
## 判断：ランキングの「月」と「地域」は別々の一覧にする

状態：提案（人の確認待ち）

前は月のボタンと地域のボタンが同じ「絞り込み」の画面を開いていたので、月のボタンは「期間」、地域のボタンは「地域」の一覧だけを開くようにした。選んだらすぐ反映して閉じる（「完了」は押さなくてよい）。1つだけ選ぶ一覧は `ChoiceSheet` として部品にした。

## 判断：「ここで刺された！」を押したら、その場でピンを立てる

状態：提案（人の確認待ち）

人の指示で、投稿の画面（`ComposePage`）と「投稿する」ボタンをなくした。押すとすぐ現在地で `POST /api/pins` を送り（スタンプなし・メモなし）、立てたピンの詳細を開く。ログインしていなければログインへ、プロフィールがなければ（403 `PROFILE_REQUIRED`）プロフィール登録へ進む。立てたあとにスタンプ・メモを足したり、位置を動かしたりする API はまだないので、それらは今はできない（API ができたら、ピンの詳細から編集できるようにする）。使わなくなった `PostPin` も消した。`StampPicker` と `MugMemo` は、編集の画面で使うつもりなので残した。

## 判断：画面に出すアプリ名を「むふ」にした（リポジトリ名・Worker 名・内部の名前は mug のまま）

状態：提案（人の確認待ち）

kokokoko0825の指示（11/19）で、画面に出る名前だけを「むふ」にした：ブラウザのタブの題名（`<title>`）、はじめの画面の見出し（「刺されMAP」→「むふ」）、蚊のアイコンの読み上げ名、`ApiCheckCard`。リポジトリ名・Worker 名（URL。decisions.md #17 で変えないと決めている）・パッケージ名・コードの名前・localStorage のキー（`mug.locationAsked` など。変えると保存した設定が読めなくなる）は mug のまま。decisions.md #17 に「画面に出す名前は『むふ』」と足すかは、チームで決めて人が書く。（記録：Claude Code）

## 判断：main に入れる前の手直し（証明書の検証、危険度の色、人のランキング、仕様書）

状態：提案（人の確認待ち）

main にマージする前に、次を直した（kokokoko0825の指示、11/19。記録：Claude Code）。

- **手元の /api 転送の証明書**：`secure: false` だと CodeQL（証明書の検証を外している）に引っかかるので、ふだんは検証する形にした。プロキシ環境などで証明書のエラーになり転送できないときだけ `MUG_PROXY_INSECURE=1 npm run dev` で起動すると外す（README に書いた）。上の「手元の /api 転送は証明書の検証を外す」はこの形に置き換え
- **危険度の円の色**：`src/lib/danger.ts` に色の値を直接書いていたのを、`index.css` の `--danger-low`・`--danger-mid`・`--danger-high` から読む形にした（frontend/AGENTS.md「色の値を直接書かない」）。色そのものは同じ
- **ランキングの「人」**：上の「ランキングは『刺された回数』と『血液型別』の2つ」は、docs/decisions.md #10（人・市町村・血液型の3種類）と食い違っていたので、kokokoko0825に確認して「人」を戻した。切り替えの名前は「人／市町村／血液型」（API はそのまま）
- **仕様書**：docs/app-spec.md の 4-1 に、今の画面の動き（ようこそから始まる、タブは3つ、押したらすぐ投稿しスタンプ・メモは API 待ち、危険度は画面で決める、位置情報のスイッチ）を書いた
