## 判断：PWA は `vite-plugin-pwa`（Workbox）で作り、アイコンは `@vite-pwa/assets-generator` で作る

- 状態：提案（人の確認待ち）

### 状況（何に迷ったか）

田中の指示（11/19）：ちゃんと PWA にしてほしい。アイコンはないので作ってほしい。PWA は docs/ のどこにも書かれていない。

### 決めたこと

- 開発用のパッケージに `vite-plugin-pwa@2.0.0`・`workbox-window@7.4.1`・`@vite-pwa/assets-generator@2.0.0` を足した
- マニフェストは `vite.config.ts` の `VitePWA` に書いた（名前「むふ」、`display: standalone`、縦向き、色は画面の背景と同じ `#f5ecc3`）
- アイコンは、今の `favicon.svg` のキャラクターを正方形の真ん中に置いた `public/icon.svg` を元にした。`npm run icons`（`pwa-assets.config.ts`）で PNG を作り、**PNG はコミットする**（ビルドのたびには作らない）
  - 普通のもの（64・192・512px、背景は透明）、maskable（512px、余白30%、背景は黄色 `#f9de86`）、iPhone 用（180px、背景は黄色）、`favicon.ico`
- `index.html` に `theme-color`・`description`・`apple-touch-icon`・iPhone 用の `apple-mobile-web-app-*` を足した
- Storybook では PWA の設定を外した（`.storybook/main.ts` の `viteFinal`）。外さないと、Storybook のビルドにも `sw.js` ができる

### 理由

- `vite-plugin-pwa` は Vite の PWA の定番で、2.0 が Vite 8 に対応している。Service Worker を手で書くと、ハッシュ付きのファイル名の一覧を自分で管理しなければならない
- アイコンを生成する道具は同じ作者のもので、PWA に要るサイズがそろう。Figma にアイコンがないので、今のキャラクターを使って見た目をそろえた
- Worker（`worker/`）は変えていない。`frontend/dist` の `sw.js`・`manifest.webmanifest` もそのまま返されるので、約束1（Worker は `/api` の中継だけ）を守れる

### ほかの案

- Service Worker を手で書く：保存するファイルの一覧と、古い保存の掃除を自分で書くことになる
- アイコンを Figma で新しく描く：今回は Figma にアイコンがなく、今のキャラクターで足りると判断した

### 影響・あとで見直すこと

- `package-lock.json` の差分が大きいが、中身は並び替わっただけ。もとからあるパッケージの版は1つも変わっていない（スクリプトで確かめた）
- アイコンを描き直したら、`public/icon.svg` を差し替えて `npm run icons` を実行する

## 判断：Service Worker で保存するもの・保存しないもの

- 状態：提案（人の確認待ち）

### 状況（何に迷ったか）

何でも保存すると、古いピンやログインの情報が残るおそれがある。何も保存しないと、圏外で画面が開かない。

### 決めたこと

- **最初に全部保存する**：ビルドした画面ファイル（js・css・html・svg・png・ico）。`storybook/` は外す。地図のライブラリを含むファイルが約1.6MB あるので、保存できる1ファイルの上限を 5MB に上げた
- **保存しない**：`/api/*`（`NetworkOnly`）。画面の代わりに返すもの（`navigateFallback`）からも `/api/` と `/storybook` は外した
- **使ったものを保存する**
  - Google Fonts の CSS：使いながら新しいものに入れ替える（StaleWhileRevalidate）
  - Google Fonts のフォント本体：1年・30件まで（CacheFirst）
  - OpenFreeMap（`tiles.openfreemap.org`）：7日・500件まで（StaleWhileRevalidate）。一度見た場所の地図は圏外でも出る

### 理由

- `/api` を保存すると、ほかの人の新しいピンが見えなかったり、ログアウトしたあとも前の人の情報が出たりする。秘密情報の扱い（AGENTS.md）から見ても保存しないのが安全
- 地図のタイルは数が多いので、件数と期間に上限を付けて、端末の容量を使いすぎないようにした

### ほかの案

- 地図のタイルを保存しない：圏外で地図が真っ白になる
- `/api` の GET を短い時間だけ保存する：古いピンが出て混乱するので、やめた

### 影響・あとで見直すこと

- OpenFreeMap の利用条件で、端末への保存に制限がないかは確かめていない。問題があれば、この保存の設定を消す

## 判断：新しい版は自動で入れ替えず、「新しいバージョンがあります［更新］」で知らせる。圏外のときはお知らせを出す

- 状態：提案（人の確認待ち）

### 状況（何に迷ったか）

PWA は画面ファイルを端末に保存するので、デプロイしても古い画面のままになることがある。自動で読み込み直すか、知らせるかを選ぶ必要があった。

### 決めたこと

- `registerType: 'prompt'`。新しい版が届いたら、画面の上に基本コンポーネント `UpdateNotice` を出す。「更新」で読み込み直し、「×」で閉じる
- 開いたままでも気づけるよう、1時間ごとに新しい版がないかを確かめる（`src/lib/pwa.ts` の `useAppUpdate`）
- 圏外になったら、画面の上に `AppNotice` で「オフラインです。ピンの読み込みや投稿はできません」を出す（`useOnline`）
- お知らせは `App.tsx` の一番外側に重ねて出す。どの画面にいても見えるようにするため
- `UpdateNotice` の「更新」と「×」は、押せる範囲を 44×44px にした（fix/ios-hig の PR の HIG に合わせた）。お知らせの上の余白には、ノッチ・ステータスバーの分（`env(safe-area-inset-top)`）を足した

### 理由

- 自動で読み込み直すと、メモやコメントを書いている途中で消えてしまう
- 圏外で投稿を押して失敗するより、先に圏外だと分かるほうがよい

### ほかの案

- `autoUpdate`（自動で入れ替えて読み込み直す）：書きかけが消えるのでやめた
- 圏外で投稿して、あとで送る（Background Sync）：位置と時刻の扱いが複雑になるのでやめた（YAGNI）
- 自前の「インストール」ボタン：Chrome・Edge はアドレスバーのボタンで足り、iPhone はボタンを出せる仕組みがないのでやめた

### 影響・あとで見直すこと

- お知らせは画面の上に重なるので、上にあるボタン（戻る など）が一時的に隠れることがある。「×」で閉じられる
- 確かめたこと（`npm run preview` と Chrome）：Service Worker の登録、画面ファイルの保存、圏外にしても開くこと、`sw.js` を書き換えたときに「新しいバージョンがあります」が出て「更新」で切り替わること、`/api` が保存されないこと
