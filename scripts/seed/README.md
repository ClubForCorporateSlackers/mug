# デモ用のダミーデータ（scripts/seed）

デモで地図・ランキングが寂しくならないよう、ダミーのユーザー・ピン・コメント・リアクションを入れるスクリプトです。

- **本物のAPI**（`https://mug.st2026ne.workers.dev/api/...`）を呼んで入れます。位置のぼかし・市町村の判定・ランキングの加算は、本物の投稿と同じくサーバーが行います（DB に直接は書きません）
- ダミーのユーザーは Cognito の管理者用のAPIで作り、`ADMIN_USER_PASSWORD_AUTH` でログインします。パスワードは実行のたびにランダムに作り、ファイルにもログにも残しません
- 書き込みは1秒に1件（DynamoDB のユニットに収めるため）
- 中身（人数・場所・件数・文例）は [seed.config.ts](./seed.config.ts) で変えられます
- 判断の記録：[docs/adr/feature-seed-data.md](../../docs/adr/feature-seed-data.md)

## 入るもの（初期値）

| もの | 数 |
|---|---|
| ユーザー | 12人（`seed-01@example.com`〜`seed-12@example.com`。血液型 A5・O4・B2・AB1。住んでいる想定の地域は東京8人・ほかの地域4人） |
| ピン | 150件（東京100件・ほかの地域50件、16か所。`npm run places` で一覧） |
| コメント | 約30件のピンに1〜3件ずつ（ピンを立てた人以外から） |
| リアクション | 約60件のピンに1〜3個ずつ（ピンを立てた人以外から） |

ピンは、その地域に住んでいる想定の人が主に立てます（約1割はほかの地域の人が旅行・出張で）。1人あたりの件数は `npm run seed`（確認だけ）で表示されます。

ピンの日時は実行した時刻（サーバーが決める）なので、すべて**実行した月のランキング**に入ります。

## 必要なもの

- Node.js（20 以上）
- AWS CLI で `aws login` 済みであること（管理者の権限。Cognito・CloudFormation・DynamoDB を使う）

## 手順

```bash
cd scripts/seed
npm install

# 1. aws login する（認証情報の期限が切れていたら、やり直す）
aws login

# 2. 確認（読むだけ。何も作らない・書かない）
npm run check
#   認証情報・スタック MugStack・アプリクライアントの設定・テーブル・API に届くかを確かめる
#   全部 OK なら次へ

# 3. 場所の確認（ネットにはつながない）
npm run places
#   場所ごとの件数・ばらまく半径と、OpenStreetMap のリンクが出る。
#   座標はおおよその値なので、リンクを開いて公園・河川敷の中にあるか見ておく。
#   ずれていたら seed.config.ts の lat・lng（河川敷は from・to）を直す

# 4. 入れる
npm run seed            # 何を入れるかを表示するだけ
npm run seed -- --yes   # 実際に入れる（6〜8分ほど）
```

- 入れたピンは `scripts/seed/.seed-state.json` に記録されます（片付けに使う。パスワード・トークンは入っていない。コミットしない）
- 記録があるときに `seed` を実行すると、二重に入らないよう止まります。わざと足すときは `--append` を付けます
- 途中で止まったら、そこまでのピンは記録に残っています。片付けてからやり直してください

## 片付け

```bash
npm run cleanup                # 何を消すかを表示するだけ（何も消さない）
npm run cleanup -- --execute   # 実際に消す（4分ほど）
```

API にはピンを消す機能がないので、片付けは**管理者の認証情報で DynamoDB と Cognito を直接操作**します（Scan は使わず、GetItem と Query だけ）。

1. Cognito で `seed-` で始まり `@example.com` で終わるユーザーを探す
2. ダミーのピンを探す：記録ファイル ＋ 設定の場所にかかる cell の Query。**userId がダミーのユーザーのものだけ**を対象にする
3. ピン1件ごとに：コメント・リアクションを消す → その月の市町村・血液型のランキングの件数を1減らす（0になったら行を消す）→ ピンを消す
4. ランキングの「人」の行を消す
5. Users の行と Cognito のユーザーを消す
6. 記録ファイルを `.seed-state.done-<時刻>.json` に名前を変えて残す

注意

- ダミーのピンに**本物のユーザーが付けたコメント・スタンプも、ピンと一緒に消えます**
- 途中で止まっても、もう一度 `--execute` すれば残りから続けて消せます
- 記録ファイルをなくしても、設定の場所（seed.config.ts）を変えていなければ、cell の Query で見つけられます

## 認証情報が読めないとき

`npm run check` の「AWSの認証情報」が NG のとき

1. `aws login` をやり直す
2. それでも読めない場合は、その場限りの環境変数に出して実行する（ファイルには保存しない）

   ```bash
   eval "$(aws configure export-credentials --format env)"
   npm run check
   ```

## 実行にかかる時間の目安

| 処理 | 件数 | 時間 |
|---|---|---|
| ユーザーの準備（Cognito とプロフィール登録） | 12人 | 約30〜40秒 |
| ピン | 150件 | 約2.5〜3分（1秒に1件。市町村の判定で1秒を超えることがある） |
| コメント | 約60件 | 約1分 |
| リアクション | 約120件 | 約2分 |
| **投入の合計** | 書き込み約340回 | **約6〜8分** |
| 片付け | 削除・更新 約660回（0.3秒に1回）＋読み込み | **約4分** |
